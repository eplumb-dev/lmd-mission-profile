LMD Mission Profile — Timing Model

Adjust step durations and route settings to see how time per stop and total route time change. The phase and step structure comes from LMD Mission Profile.drawio. Ideal Mission Timing is a set of target values you enter. Field Data Mission Timing is filled in from CSV logs of routes you've already run. Field vs Ideal Comparison puts one stop from each side by side. The Ideal values are saved in the page URL so you can share them. Imported field data is kept in this browser.

Import one or more CSV files from routes you've already run. The model takes each step's mean, median or 90th-percentile duration from the data and uses it for the Field data timing. Field Data mode is separate from your Ideal inputs: any step missing from the data uses a built-in default value and is drawn as a transparent box.

Accepted CSV formats

Wide (one row per stop). Each column is a step, for example route, stop, park, openDoors, …, navToZone, …, putInDrive. Column names can be the step keys from the template or the step labels shown on this page, such as "Deploy stairs". Route-level columns (vehiclePrep, driveToStop, completeRoute) only need a value on one row per route. Leave a cell blank if a step wasn't measured.

Long (one row per step event). This needs a step column and a seconds or duration column. route and stop columns are optional. Without a stop column, each "Park" row starts a new stop.

Robot text log (for example …TextLogProto.csv). This uses the Log ID column (one stop per Log ID) and the Message column, reading lines like step=DISMOUNT_VAN active= 9.20s paused= 0.00s. Recognized steps: POWER_ON_STAND, ALIGN_TO_VAN_INTERIOR, DISMOUNT_VAN, LOCALIZE_POINT_CLOUD, NAVIGATE_TO_DELIVER, DEPOSIT_PACKAGES, NAVIGATE_TO_MOUNT, ALIGN_TO_VAN_EXTERIOR, MOUNT_VAN, ALIGN_TO_VAN_INTERIOR_STOW, SIT_POWER_OFF. DEPOSIT_PACKAGES is split across the four Deposit sub-steps in proportion to their default values. Stops on route keeps its default value, because a log export doesn't necessarily cover a whole route.

Durations can be written as seconds (12.5) or as mm:ss / hh:mm:ss. Without a route column, each file counts as one route. Stops per route and robot trips per stop are counted from the data.

Navigate still uses distance ÷ speed. If the data has measured navigate times, the speed is set so that distance ÷ speed matches them. You can also supply navSpeed (m/s) and navDist (m) columns.

Where the route time goes

Model assumptions

  • Route: Vehicle Prep (once) → Drive to Stop (depot to first stop) → Delivery → Navigate to Next Point (between stops, repeated) → Complete Route (once).
  • Delivery = Stop Initialization → Autodeliver (Prepare for Delivery, Navigate to Delivery Zone, Deposit, Navigate to Van, Complete Delivery) → Stop Reload.
  • Navigate (to delivery zone) and Navigate (to van) each take distance ÷ speed. Both legs use the same distance, and the time is calculated rather than typed in.
  • Robot trips per stop > 1 repeats Load Package → Navigate to Zone → Deposit → Navigate to Van for each extra package.
  • Field data: each step uses one summary value (mean, median or 90th percentile) across every imported occurrence. Field mode doesn't use your Ideal inputs. Steps and route settings missing from the data use the built-in default values, are tagged default, and are drawn as transparent boxes. Values you edit in Field mode sit on top of the imported values. "Reset" removes those edits. The per-stop breakdown in Field mode covers one stop only.
  • Durations are fixed per step. The model assumes no parallel work, failures, or retries.
